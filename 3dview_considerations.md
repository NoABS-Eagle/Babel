# 3D-вьюпорт будущего редактора — соображения (2026-07-10)

Статус: КОНЦЕПТ, не план работ. Зафиксировано из обсуждения, чтобы не перепройти
цепочку рассуждений. Ничего из этого не касается IR: весь 3D живёт в редакторе,
формат про него не знает (кроме уже спроектированного `<model3d>`-диспетчера).

## Рамка: «немного mCAD» — самое нужное за самое дешёвое

Редактор получает mCAD-возможности, но ровно те, что закрывают главные боли и
стоят дёшево. Границы, которые держат скоуп:

1. **Редактор никогда не создаёт и не изменяет ТЕЛ.** Импортированные B-rep'ы
   (корпус, окружение) неприкосновенны. Единственная 3D-сущность, создаваемая
   пользователем, — кривая (путь жгута), и это наш родной канон отрезков/дуг,
   просто с третьей координатой. Первоначальная формулировка «read-only
   геометрия» уточнена именно так: read-only — тела, не всё подряд.

2. **Дёшево = запросы к геометрии, дорого = создание геометрии.** Расстояние,
   пересечение, кривизна, проекция, сечение — да. Sweep-как-тело, булевы,
   скругления, параметрика, сборки со связями, допуски, чертежи — нет
   (это «плохой SolidWorks вместо хорошего PCB-редактора»). Проверочный
   критерий для каждой будущей хотелки.

3. **UI-граница дешевизны: точка на существующей геометрии vs точка в пустоте.**
   Клик-рейкаст по поверхности (третью координату даёт поверхность) — дёшево.
   Свободная точка в пустом 3D (гизмо трёх осей, рабочие плоскости) — дорого,
   эта категория инструментов НЕ открывается. Минимальный обязательный набор:
   перемещение моделей (transform-гизмо жёсткого тела) + align (грань-к-грани,
   рейкасты). Плату этими инструментами не двигаем — она рождается из проекции
   (см. ниже).

4. Признак правильно проведённой границы, который повторился на каждой фиче
   этого документа: **фичи складываются друг в друга, а не громоздятся рядом**
   (одна машинерия, много ручек).

## Окружение платы

- Окружение (модель корпуса и пр.) — **свойство компоновки платы**, 1:1,
  прикрепляется вручную. Никаких отдельных сущностей «кандидат компоновки»,
  никаких кросс-продуктов плат×корпусов (отвергнуто: под другой корпус разъёмы
  всё равно едут — «одна раскладка × много корпусов» — выдуманный сценарий).
- Перебор вариантов устройства = несколько компоновок на одну схему (уже есть
  в модели проекта), у каждой своё окружение. Инвариант: состав компонентов
  общий (схема одна). Умерла гипотеза — удалилась компоновка, следов нет.
- «Быстрый интерфейс просмотра» = листалка по компоновкам проекта, каждая
  тащит своё окружение. Новой модели данных ноль.
- Экспорт наружу: STEP сборки — механику (плата с компонентами как тело в его
  системе координат), рендер/glTF — показать людям.
- Анти-скоуп: никакой персистентности сверх «своё окружение у компоновки» —
  история ревизий корпуса, статусы согласования и т.п. = PDM, чужое болото.

## Инструмент ПРОЕКЦИЯ (3D → особый 2D-слой)

Замена сегодняшнего ритуала «механик экспортирует DXF → импорт → ручное
выравнивание → молитва об актуальности». Корпус уже стоит на месте в 3D —
проецируем напрямую.

- Режимы (одна машинерия): **силуэт** выбранного тела («где стоит разъём»),
  **сечение на высоте Z** (вырезы под кнопки/светодиоды — по внутренней
  поверхности крышки), **проекция всего, что вторгается в высотный диапазон**
  над платой (= автогенерация высотных запретных зон от стоек/рёбер).
- Результат — **обычные кривые на особом слое** + пометка «из чего испечено»
  для «источник изменился — перепеки». НЕ живая зависимость 2D-документа от
  3D-файла. В IR никакого нового типа: примитивы на слое, магия в редакторе.
- Воркфлоу рождения платы: указать плоскость платы → проекция крепёжных
  отверстий и границ на особый слой → в 2D обвести нужное на слое 120 → плата
  ровно там, где должна. (Это НЕ нарушение read-only: корпус не редактируется,
  из него проецируется. Тот же приём, что у Fusion360 — который сам унаследовал
  «project geometry в эскиз» из Pro/E; мы берём из этого воркфлоу два примитива
  без остального mCAD.)
- Противное место (где основная работа): тесселированный источник даёт на
  сечении полигональную труху вместо дуг. Либо аналитическая геометрия STEP
  (сечение цилиндра сразу даёт нашу концевую дугу), либо распознавание дуг в
  полилиниях постфактум.

## Инструмент OFFSET (2D, контур с зазорами)

Нужен сразу вслед за проекцией (обвёл крепёж — получил контур с зазором).

- Локально тривиален (отрезок→отрезок, дуга→дуга r±d), глобально — класс
  булевых по коварству (самопересечения при офсете внутрь, невалидные петли).
  **С нуля не писать.**
- Готовое: **CavalierContours** (C++/Rust) — полилинии «вершины + bulge»,
  отрезки и дуги первоклассные, без тесселяции; bulge = tan(θ/4), пересчёт
  из нашего x1y1x2y2+curve — одна формула без потери точности. Запасной —
  Clipper2 (железобетонный, но дуг не знает: рубить/распознавать).
- Окупается трижды: контур платы; **отступы полигональной заливки** (буквально
  та же операция — см. отложенную в decisions.md «семантику контура полигона»
  2026-07-09: нормализация Eagle-полигонов офсетом на width/2 — ЭТОТ ЖЕ движок);
  проверка минимальной ширины.
- Содержательное решение на потом: офсет открытых цепочек (торцы), для платного
  сценария почти всегда замкнутый случай.

## Механический DRC — класс проверок

«Как DRC, только механический». Почти всё семейство — один примитив
**signed distance между телами**:

- пересечение (d < 0);
- **зазор** «не ближе чем» (крышка ↔ конденсатор при допусках литья);
- **обязательный контакт** «не дальше чем» — перевёрнутый знак неравенства:
  термопрокладка обязана быть сжата (зазор < её толщины). Электрический DRC
  такого не умеет в принципе;
- **соосность** (ось кнопки ↔ ось выреза; крепёжное отверстие ↔ бобышка,
  плюс диаметры).

Второй ингредиент — **фантомные «рабочие объёмы»** в 3D-модели компонента:
тело ответной части разъёма (штекер + пальцы), цилиндр доступа отвёртки над
винтом, выход кабеля. Не печатаются, не рендерятся в сборке — участвуют только
в проверках пересечения с корпусом. Ложится на спроектированный 3D-диспетчер
(`<model3d>`): ещё одно тело в модели, помеченное ролью. Авторятся снаружи, в
настоящем mCAD — редактор их не моделирует (граница №1 не нарушена).

Дешёвые проверки вообще без тел: высотный габарит компонента против высотной
карты (из проекции), толщина платы против паза.

Анти-скоуп (анализ ≠ проверка; решатель ≠ линейка): допусковые цепочки с
распределениями, гибкие тела как симуляция, тепло, вибрация.

## Жгуты: резервирование вместо предсказания

Главная боль собираемости — проводка всегда занимает больше места, чем
ожидаешь; хорошего учёта на этапе проектирования нет ни у кого. Существующие
решения (SolidWorks Routing, Creo Cabling) — симуляция гибкого тела, дорого,
хрупко и врёт (монтажник уложит иначе). Наш ответ — не предсказывать, где
провод ляжет, а **резервировать, где ему разрешено лежать**. Декларация, не
симуляция — то же «никаких эвристик».

- Путь жгута — кривая, нарисованная человеком (топологию трассы решает
  человек, автопрокладки НЕТ).
- Диаметр пучка — из состава (число×сечение, эмпирическая формула упаковки) ×
  честный коэффициент распушения: «занимает больше, чем ожидаешь» превращается
  из сюрприза в константу.
- Проверки — sweep НЕ НУЖЕН, труба никогда не существует как тело:
  «труба радиуса r пересекает корпус» ⟺ «расстояние от КРИВОЙ до корпуса
  < r + зазор» — капсула, второй по дешевизне примитив коллизий. Радиус
  изгиба — аналитическая кривизна кривой против минимума самого толстого
  провода. Во вьюпорте труба — декоративная тесселяция, в проверках не
  участвует.
- **Ввод пути — только рейкастами**: концы НЕ указываются (оси выхода
  разъёмов из фантомных объёмов), промежуточные точки ставятся ТОЛЬКО кликом
  по поверхности. Это не удешевляющий компромисс, а более честная модель:
  реальный жгут притянут к поверхностям стяжками — точка перегиба в пустоте
  в собранном устройстве не существует. Оттяжка от стенки — скаляр вдоль
  нормали, ползунок. Безалаберно проложенный жгут в редакторе НЕВЫРАЗИМ —
  hard reject на уровне инструмента, не проверка постфактум.
- Бесплатные побочные продукты: длина реза (путь + сервисные петли) и
  **монтажная инструкция** — каждая точка пути по построению = «здесь стяжка
  к вот этой поверхности»: список креплений, порядок укладки, длины — уже в
  данных, ждут кнопки экспорта.
- Каскад, ради которого всё записано: ограничение введено ради дешевизны UI →
  оказалось физически честнее свободного сплайна → оказалось документацией для
  сборки. Одно решение окупилось трижды в несмежных местах.
- Анти-скоуп: автопрокладка, гравитация/драпировка, развёртка жгута в плоский
  чертёж с гвоздевой доской (Zuken E3 / Siemens Capital — отдельная индустрия).
- Фича **отрезаема**: механический DRC на ней не стоит; если поверхностный
  ввод пути окажется противнее, чем выглядит, — в deferred без потерь для ядра.
