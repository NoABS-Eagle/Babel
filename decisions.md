# PCB Editor — Важные архитектурные решения

## Язык и фреймворк
- **C + raylib**
- Приоритет: производительность, простота, нативные инструменты

## Система координат
- **int32_t в микрометрах**
- Диапазон ±2147 метров — достаточно
- Дюймовые единицы (mil) — только на границе импорта/экспорта, конвертация при чтении
- Ошибки округления в единицы микрометров физически неощутимы

## Хранение объектов
- **Tagged union array** с абстракцией через ObjRef `{ ObjType type; int index; }`
- Cache miss не проблема на реальных объёмах PCB
- Переход на per-type массивы возможен без изменения внешнего кода — ObjRef скрывает реализацию

## Удаление объектов
- **Tombstone** — помечать удалёнными, не двигать массив
- Индексы остальных объектов не инвалидируются

## Память для геометрии
- Фиксированные объекты (трассы, виа, пады) — **arena allocator** внутри Board
- Зоны — **исключение**: динамический массив точек через malloc/realloc
- Зоны редактируются активно, arena для них не подходит

## Undo/Redo
- **Full board snapshot** (deep copy)
- Для зон — отдельный memcpy массива точек
- ~5 МБ на снапшот для типичной платы, 20 уровней = ~100 МБ — приемлемо
- Оптимизация до delta snapshot — только если станет реальной проблемой

## Файловый формат
- **Рабочий формат**: Eagle .brd (XML) — читаем и пишем
- **Экспорт**: KiCad .kicad_pcb, Gerber — добавить позже
- Eagle .brd самодостаточен: вся геометрия футпринтов внутри, библиотеки не нужны
- Метаданные которые не редактируем (contactref, designrules, библиотечные ссылки) — хранить как passthrough XML блок
- Round-trip безопасен: меняем только позиции элементов и геометрию сигналов

## Eagle → KiCad экспорт схемы
- Правильный путь: экспорт библиотек из Eagle → импорт в KiCad → импорт схемы
- Гарантированное покрытие всех символов, никакой самодеятельности
- Парсер .lbr переиспользует код парсера .brd

## Слои
- Числовой индекс + таблица свойств `LayerInfo { name, color, visible, locked, is_copper, eagle_id }`
- Фиксированный набор стандартных слоёв + пользовательские (произвольное количество)
- Eagle числа → наши имена через таблицу маппинга при импорте
- Порядок отрисовки — отдельный массив индексов, меняется через CLI (`layer order ...`)
- GUI визард для порядка слоёв не нужен — CLI проще и точнее

## Нетлист и ратснест
- Нетлист читается из Eagle .brd секции `<signals>` — там уже всё есть
- Каждый пад знает свой net_id
- Ратснест = MST (алгоритм Прима/Крускала) по несоединённым падам каждой цепи
- Пересчёт в фоновом потоке, dirty flag на каждой цепи
- **Ратснест контекстный** — показывается не всё сразу:
  - Ничего не выбрано → ратснест скрыт (или бледный по явному запросу)
  - Выбран футпринт → только его соединения
  - Идёт маршрутизация → только текущая цепь

## Rooms (группы компонентов)
- Простой прямоугольник с именем, без привязки к иерархии схемы — в отличие от Altium
- Любая схема, в том числе однолистовая, может использовать rooms без церемоний
- Ратснест **раскрашивается по rooms**: внутриблочные соединения одним цветом, межблочные — другим
- При компоновке можно скрыть внутриблочный ратснест — видна только общая картина связей между блоками
- Начальный импорт: компоненты с одного схемного листа → одна room, расставляются вместе
- Хранить как отдельный объект платы: `Room { name, rect, color }`
- Eagle groups → rooms при импорте (если есть)

## Группы объектов
- Группа — только для быстрого выбора, не блокирует индивидуальный выбор объектов
- Объекты выбираются по одному как обычно; группа выбирается через отдельное поле в интерфейсе
- Группа может содержать любые ObjRef включая rooms
- `Group { name, ObjRef *members, int count }`

## Умное перемещение группы
- При move группы — автоматически подхватываются трассы у которых **оба конца** принадлежат компонентам группы
- Трассы с одним концом внутри, другим снаружи — предупреждение в строке статуса
- Трассы с обоими концами снаружи — не трогаются
- Пересоздавать группу с дорожками вручную как в Eagle — не нужно, редактор знает топологию сам

## Zone Fill
- Библиотека полигональных операций: **Clipper2**
- Пересчёт в **фоновом потоке**, worker спит 16мс между проходами
- **Dirty flag** на каждой зоне — пересчитывать только затронутые
- **Пространственный индекс** — искать только объекты рядом с зоной, не все
- Worker работает с копией данных зоны во избежание гонок
- **Фаза 1**: обновление fill после каждого зафиксированного действия пользователя
- **Фаза 3** (после профилирования): обновление в реальном времени через ghost object

## Рендеринг полигонов
- Триангуляция через **earcut** — один `.h` файл, ~500 строк, поддерживает дырки
- Дырки в fill зоны — результат Clipper2 (зазоры вокруг падов, трасс)
- Триангуляция кэшируется в зоне, пересчитывается только после zone fill (когда dirty)
- Рендер: контур зоны (линии по точкам) + залитая медь (кэшированные треугольники)
- Приоритет зон: `fill_priority` — зона с высшим приоритетом заливается первой
- Пересекающиеся контуры зон — не ошибка на этапе рисования, разруливается при fill

## Выбор объектов (Selection)
- Пад — не объект выбора вообще. Часть футпринта, данные для DRC/ратснест/рендера
- Футпринт выбирается **только по origin** — как в Eagle
- Приоритет при наслоении: **Трасса > Виа > Футпринт origin > Зона**
- ЛКМ — выбрать первый по приоритету
- ПКМ — перебрать следующий объект в стеке под курсором (без меню, без тултипов)
- Флаг `selected` хранится прямо в объекте
- Box select: слева направо — только полностью вошедшие, справа налево — любое пересечение
- Никаких всплывающих свойств при наведении — только явный запрос пользователя

## Фильтр выбора объектов
- Панель тогглов всегда на экране — тип объекта + слой
- Визуальная индикация что сейчас можно выбрать — состояние видно постоянно
- Простой Eagle-подход: чекбоксы по типу (трассы, виа, футпринты, зоны, текст) и по слою
- Сложные фильтры через CLI если нужно, но основной инструмент — GUI панель

## Пространственный индекс
- **Равномерная сетка** — достаточно для PCB, проще R-tree
- Размер ячейки ~1-2мм
- Объект регистрируется во всех ячейках которые перекрывает его bbox
- При хитресте: берём ячейки под курсором + соседние, точная проверка только кандидатов

## Архитектура инструментов
- Каждый инструмент — vtable `Tool` с функциями: activate, deactivate, on_lmb, on_rmb, on_move, on_key, render
- Каждый инструмент — отдельный `.c` файл, своё статическое состояние
- Активен ровно один инструмент, переключение через `set_tool()`
- Инструмент мутирует плату через транзакционный API (board_begin/commit) — undo автоматически
- Добавить новый инструмент = написать один `.c` файл, не трогая остальное
- Ghost/preview рисуется в `render()` инструмента, не затрагивает модель

## Командная строка
- Отдельная сущность — парсер команд с доступом к модели и состоянию редактора
- Мутации через те же транзакции что и инструменты — undo работает автоматически
- Два типа команд: мутации модели (`move C8 (1 5)`) и навигация/состояние (`show C8`, `grid 0.1`)
- Обсудить детально позже

## Принцип CLI vs GUI
- **CLI для действий** — выполнил и забыл (`move C8 (1 5)`, `layer order ...`)
- **GUI для состояния** — должно быть видно постоянно (фильтр выбора, активный слой, сетка)

## Принцип деструктивных операций
- Не спрашивать подтверждения — дать возможность отменить через Undo
- Информировать в строке статуса: "U3: 12 трасс отсоединено"
- Модальные диалоги не использовать

## Набор инструментов первой версии
- **Select** — box left/right + фантомный полигон даблкликом
- **Route+Via** — трассировка + виа одним инструментом
- **Move** — отдельный инструмент, НЕ часть Select
- **Zone** — контур зоны
- **Measure** — расстояние
- **Text** — надпись на слой
- **Line** — линия/дуга на слой
- **Drill** — механическое отверстие
- **Mirror/Flip** — компонент на другую сторону, трассы становятся ратснестом молча
- **Miter/Fillet** — скругление углов трасс после трассировки
- **Dimension** — задание расстояния между объектами (одноразовый constraint solver)
- Place Footprint — не нужен в первой версии, все компоненты из .brd
- Align — не нужен вообще (Eagle 7.7 его не имел, Eagle 9.6 крашится при попытке)

## Инструмент Move
- Клик на невыделенный объект + M → берёт за origin, снапит origin к сетке
- Выделенная группа + M или drag → берёт за точку захвата, двигает всё выделенное
- Одиночный объект — частный случай группового сдвига
- Точное перемещение через CLI: `move C8 +5 0` (относительное), `move C8 (10 5)` (абсолютное)

## Инструмент Route — геометрия
- Режим заданного угла (дефолт 45°, но любой) — обобщение 45° и 90° режимов
- Свободный угол
- Скругление — отдельный инструмент Miter после трассировки, применимо ко всему выбранному сразу
- Безье не нужны

## Инструмент Route — поведение
- Только ручной маршрутизатор — никакого push-objects, никакого автоогибания
- Два режима DRC: свободный (подсвечивает но не блокирует) и строгий (блокирует)
- Переключение режима DRC — одна кнопка, состояние видно в GUI постоянно

## Инструмент Route — параллельность и угол
- Shift+клик на любую прямую на любом слое → snap_angle = угол этой прямой
- Повторный Shift+клик на тот же объект → snap_angle += 90°
- Циклически: параллельно → перпендикулярно → параллельно
- Старт трассировки от пада повёрнутого компонента → snap_angle автоматически = угол компонента

## Инструмент Dimension
- Не аннотация — задание расстояния. Одноразовый constraint solver
- Снап к характерным точкам объектов (центр, края, концы трасс, origin)
- Если угол между объектами больше порогового (настраивается, дефолт ~5°) — не выполняется
- Механика характерных точек переиспользуется в Route и других инструментах

## Операция параллельности
- Не отдельный инструмент — операция над выделенным объектом
- Выделил объект → нажал клавишу → Shift+клик на референс → объект повернулся параллельно
- Повторный Shift+клик → перпендикулярно (та же механика что в Route)
- Применимо к трассам, линиям, футпринтам
- Касательная — не нужна, реальных сценариев на плате нет

## 3D просмотр
- 3D вид — ещё один рендерер той же Board структуры, не отдельное приложение
- Обновляется в реальном времени вслед за изменениями в редакторе
- Три типа изменений с разной стоимостью:
  - Компонент переместился → обновить матрицу трансформации + перегенерировать текстуру меди (быстро)
  - Трасса добавлена → перегенерировать текстуру меди (быстро, тот же код что 2D рендер)
  - Контур платы / отверстие изменились → регенерировать меш в фоновом потоке (медленнее, но редко)
- Текстуры меди генерируются рендером 2D слоёв в offscreen framebuffer — переиспользование кода
- Компоненты — меш-модели из .step/.wrl с матрицей трансформации
- Dirty флаги по типу изменения: `copper_dirty`, `outline_dirty`, `components_dirty`
- Те же dirty флаги что для zone fill — один механизм, два потребителя
- Предусмотреть сейчас: не выбрасывать 3D данные при импорте .brd (путь к модели, offset, rotation, scale)

## Design Rules
- Параметры от производителя, задаются один раз для проекта:
  `min_trace_width`, `min_clearance`, `min_via_drill`, `min_annular_ring`
- Параметры инструментов не дают ввести значение меньше чем в design rules
- При смене design rules — автоматический полный DRC, подсветка новых нарушений
- Acid traps — не нужны, современные производители справляются без проверки

## DRC
- Фоновый поток, та же архитектура что zone fill и ратснест:
  dirty flag → пересчёт только затронутого → обновление списка нарушений → подсветка
- Два режима во время трассировки: свободный (подсвечивает) и строгий (блокирует)
- Пространственный индекс обязателен — проверять только объекты в радиусе max_clearance
- Три фоновых потока с одинаковой структурой:
  - `zone_fill_worker` — dirty zones → новый fill
  - `ratsnest_worker` — dirty nets → новый MST
  - `drc_worker` — dirty objects → новые нарушения
- Возможно объединить в один поток — решить после профилирования

## Автоматический ратснест
- Ратснест обновляется автоматически без кнопок и церемоний
- Положил трассу, соединил пады — ратснест между ними исчез сам
- Пересчёт MST для типичной цепи — микросекунды, нет причин делать вручную

## Многоканальное проектирование
- Многоканальная схема = особый вид библиотечного компонента (иерархический)
- На схеме инстанцируется как обычный компонент, референсы назначаются автоматически
- На плате = модульный футпринт: дочерние футпринты + трассы + виа + геометрия
- Обновил определение модуля в библиотеке → все инстансы на плате обновились
- Маппинг компонентов между каналами не нужен явно — решается иерархией схемы
- Назначение референсов многоканальной схемы — особый случай схемного редактора

## Иерархия футпринтов
- Футпринт может содержать дочерние футпринты — рекурсивная структура
- Рекурсивный обход дерева проще чем два разных кода для разных уровней
- Максимальная глубина вложенности — константа `MAX_NESTING_DEPTH`
- Ограничение глубины — одна проверка в одном месте, не затрагивает рекурсивный код
- Реальных сценариев глубже 2 уровней нет, но архитектура не ограничивает
- Финальное решение по максимальной глубине — после дополнительного обдумывания

## Тип Shape
- Отдельный тип в модели данных — не рассыпается на линии, редактируется как единое целое
- Параметры: `pos, size_x, size_y, roundness (0-100), width (0=залитая, >0=контур), rotation, layer`
- Круг: `size_x == size_y`, `roundness == 100`
- Залитый квадрат: `size_x == size_y`, `roundness == 0`, `width == 0`
- Line — отдельный примитив для произвольных линий, Shape использует его концептуально но не хранит
- Геометрия генерируется на лету при рендеринге из параметров
- **Выбор по контуру** — консистентно с зонами и линиями

## Тип Pad
- TH и SMD — два отдельных типа, не объединять
- Причины: разная логика в DRC, zone fill, Gerber экспорте, фильтре видимости
- Форма пада: `size_x, size_y, roundness (0-100)` — вместо enum типов
- Круглый пад: `roundness == 100`, квадратный: `roundness == 0`
- Восьмиугольник и овал при импорте → круг (ошибки округления подсветит DRC)

## Принцип консистентности как документация
- Все объекты выбираются по контуру — зона, Shape, линия, незалитая и залитая фигура
- Все инструменты используют Shift+клик для параллельности
- Все деструктивные операции молча выполняются и отменяются через Undo
- Пользователь выучивает паттерн один раз — документация для базовых операций не нужна

## Термобарьеры
- Настройки: включено/выключено + зазор между падом и полигоном
- Ширина спиц = width полигона
- Ориентация спиц = угол пада (как в Eagle)
- Четыре спицы, всегда — фиксированный разумный дефолт
- Особые термобарьеры для конкретного участка — отдельный полигон с нужными настройками и приоритетом
- Никакой отдельной системы назначения термобарьеров падам — полигон уже является единицей настроек

## Модули (многоканальные схемы)
- Модуль — отдельный файл платы (.brd), открывается и редактируется как любая другая плата
- Никакого "редактора внутри редактора" — просто открыл файл модуля, отредактировал, сохранил
- При открытии основной платы Swift проверяет timestamp файлов модулей и предлагает применить изменения:
  `Модуль power_channel.brd изменился. Применить к 3 инстансам? [Применить] [Пропустить]`
- Работает и для модулей используемых в нескольких проектах — тот же механизм бесплатно
- Инстанс модуля на плате = ссылка на файл + позиция/трансформация

## Футпринты vs Модули
- **Футпринт** — неизменяемый, геометрия определяется физическим компонентом, хранится в библиотеке совместимой с Eagle
- **Модуль** — редактируемый файл платы, специфичен для проекта, не библиотека
- Два разных объекта с разной семантикой — не объединять

## Detach инстанса модуля
- Detach — разворачивает модуль в плоскую структуру обычных объектов платы
- После detach: нет ссылки на файл модуля, полная свобода редактирования, нет обновлений
- Необратимо (кроме Undo) — один из редких случаев где предупреждение оправдано
- Detach помечает инстанс для будущей синхронизации со схемным редактором

## Открытый вопрос — detach и схемный редактор
- Detach на плате должен как-то отражаться на схеме
- Варианты: синхронный detach, только на плате, запретить detach без схемы
- Решить когда дойдём до проектирования схемного редактора

## Инструмент Route — подсветка запретных зон
- При активной трассировке подсвечивать зоны куда трасса не пройдёт по DRC
- Технически: expand(obstacle, clearance + width/2) — тот же Minkowski sum что при zone fill
- Только объекты рядом с курсором через пространственный индекс — быстро
- Полупрозрачная заливка запретных зон — пользователь сразу видит куда пролезет
- Лучше чем push obstacle: не двигает ничего, просто показывает реальность
- Пересчёт при каждом движении мыши только в радиусе нескольких миллиметров

## Изображения на плате (логотипы, штрихкоды)
- Принимаем только растр (PNG/JPG) — SVG не поддерживаем, пользователь конвертирует сам
- В редакторе рендерится как растр, масштабируется и перемещается как обычный объект
- При экспорте Gerber — автоматическая векторизация через potrace
- DRC шелкографию не проверяет — пользователь смотрит в 3D вид
- Инвертированный текст — полигон на шелкографии + объект с флагом subtract

## Инструмент Split (разрезание трассы)
- Два клика — начало и конец вырезаемого участка
- Сегмент удалён, пользователь ставит новый нужной ширины
- Явное действие пользователя — явный результат, ничего автоматического
- Автосужение трасс не делаем — ширина трассы выбирается осознанно и не должна меняться незаметно

## Инструмент Route — отмена действий
- Backspace во время трассировки — отменить последний сегмент, остаться в инструменте
- Esc — отменить всю трассу, выйти из инструмента
- Ctrl+Z после завершения — отменить всю трассу как одно событие
- Перезаливка полигона происходит после каждого зафиксированного сегмента — не ждёт конца трассировки
- Undo оперирует транзакцией (вся трасса), рендер обновляется постоянно — два разных механизма

## Умный буфер обмена
- Ctrl+C / Ctrl+V работает между разными открытыми проектами
- При вставке: референсы переименовываются автоматически (R1→R5 если R1-R4 заняты)
- При вставке: сети с общими именами (GND, VCC) соединяются с существующими, уникальные создаются новыми
- Копирует и схему и трассировку вместе
- Внутри одного проекта — инструмент для быстрого повторения каналов без модулей
- Не требует документации — люди будут пользоваться инстинктивно

## Модули — уточнение концепции
- Единственная причина использовать модуль — живая связь: изменил в одном месте, обновилось везде
- Для всех остальных случаев повторного использования — умный буфер обмена
- Модуль как "квадратик для читаемости" не нужен — на бесконечном холсте без листов читаемость решается зумом

## Скриптинг
- Встроенный язык скриптинга — **Lua**
- ~300 КБ весь интерпретатор, встраивается в C за час
- Полный доступ к модели данных — читать и модифицировать компоненты, трассы, сети, свойства
- Простые скрипты — просто набор CLI команд в файле
- Сложные скрипты — Lua с биндингами к модели, как ULP в Eagle и Python в KiCad
- Lua проще ULP, документации больше, ChatGPT пишет скрипты по описанию

## Импорт BSDL для создания компонентов
- BSDL файлы содержат имена и типы всех пинов чипа — идеально для создания УГО
- Правильный workflow: свой проверенный футпринт + имена пинов из BSDL = готовый компонент за секунды
- Не использовать Ultra Librarian BXL для футпринтов — качество низкое, много мусора
- При открытии редактора УГО явно показывать варианты импорта включая BSDL — discoverability важна
- Редактор должен намекать на существование BSDL чтобы пользователи не узнавали об этом случайно через 15 лет
- Настройка рендеринга слоёв (цвет, прозрачность, заливка) — GUI, не CLI, нужен мгновенный визуальный фидбек

## Полигоны — пересмотр подхода
- Стоит протестировать Eagle-подобный scanline/штриховочный алгоритм против Clipper2
- Eagle работал быстрее KiCad именно из-за простоты линейного алгоритма vs тяжёлые полигональные операции
- Width параметр полигона как защита от производственного брака — не баг а фича
- Штрихованный полигон естественно маппится на сетку сопротивлений для PI анализа
- Clipper2 для этого требует дополнительного шага мешинга

## GPU DRC и рендеринг
- Растровый DRC: каждый пиксель = 1 микрон нашей системы координат
- Максимум GPU текстуры ~16384x16384 — при 1мкм/пиксель покрывает только 16x16мм
- Решение: тайловая система — одна большая составная текстура как MegaTexture (id Software, Quake Wars 2007)
- Детальные тайлы подгружаются по мере приближения камеры, вдали — низкодетальные
- DRC считается только локально вокруг курсора на детальных тайлах
- Три SDF шейдера покрывают всю геометрию платы: круг, прямоугольник/отрезок, дуга
- Нарушения DRC показываются визуально на плате — красные области, не текстовые отчёты
