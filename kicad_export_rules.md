# Обращение с футпринтами и атрибутами при экспорте IR → KiCad

## Выходные артефакты

| Артефакт | Имя | Формат |
|---|---|---|
| Символьная библиотека | `{lib_name}.kicad_sym` | S-expressions |
| Библиотека футпринтов | `{lib_name}.pretty/` | папка с `.kicad_mod` файлами |

Оба артефакта создаются всегда, независимо от содержимого IR.

---

## Правила экспорта символов

### Компонент с одним футпринтом

- Символ экспортируется полностью
- Поле `Footprint` = `{lib_name}:{footprint_id}` — корректная ссылка в `.pretty`-библиотеку
- Все атрибуты заполнены значениями из IR

### Компонент с несколькими футпринтами

- Символ экспортируется как обычно (геометрия, пины)
- Поле `Footprint` — пустое (пользователь назначает корпус сам в PCB-редакторе)
- Поля атрибутов присутствуют, но **значения пустые**
- Это соответствует стандартному KiCad-воркфлоу: символ = логическая деталь, корпус = решение при проектировании

### Компонент без футпринтов (устройство без корпуса)

- Символ экспортируется как обычно
- Поле `Footprint` — пустое
- Атрибуты заполнены из IR

### Орфан-символ (символ, не входящий ни в одно устройство)

- **Не экспортируется**
- Орфан-символ — незавершённый артефакт Eagle (геометрия без компонентной обёртки)
- В KiCad нет эквивалентного понятия, экспорт лишён смысла

---

## Правила экспорта футпринтов

- Каждый `<footprint>` из IR → отдельный файл `{footprint_id}.kicad_mod` в `.pretty`-папке
- Это касается как футпринтов внутри компонентов, так и orphan-футпринтов (без символа)

---

## Обоснование

Единица экспорта — **устройство (component)**, не символ и не футпринт по отдельности.
Символ — это часть устройства. Футпринт — тоже часть устройства.

Библиотека — шаблон с вариантами. Схема — принятое решение.  
В схеме каждый экземпляр компонента всегда имеет ровно один корпус и полный набор атрибутов,
поэтому потери при экспорте библиотеки с несколькими футпринтами — только косметические.
При экспорте схемы неоднозначности нет никогда.
