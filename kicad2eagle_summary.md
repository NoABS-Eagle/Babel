# KiCad → Eagle конвертер — выжимка проекта

## Что делаем
Утилита импорта KiCad проекта (схема + плата) в Eagle. Плюс попутно Eagle → KiCad как второе направление на той же базе.

---

## Архитектура

```
KiCad проект
     ↓
Python парсер (.kicad_sch + .kicad_pcb)
     ↓
Промежуточная модель (AST)
     ↓
Генераторы Eagle XML
     ↙        ↓         ↓        ↘
Device.lbr  MCU.lbr  proj.sch  proj.brd
                                   +
                      _footprints.lbr  (для glue)
```

Обратное направление — другой генератор из той же промежуточной модели.

---

## Входные данные
Пользователь указывает папку KiCad проекта:
```
my_project/
├── my_project.kicad_pro
├── my_project.kicad_sch      ← схема (главный лист)
├── my_project.kicad_pcb      ← плата (футпринты встроены целиком)
├── sheets/                   ← доп. листы если есть
│   └── *.kicad_sch
└── libraries/                ← локальные библиотеки
    ├── *.kicad_sym           ← символы (могут быть НЕ встроены в sch!)
    └── *.pretty/
        └── *.kicad_mod
```

---

## Выходные данные
```
my_project/
├── Device.lbr                ← библиотека из KiCad библиотеки Device
├── MCU_ST_STM32F1.lbr        ← библиотека из KiCad библиотеки MCU_ST_STM32F1
├── Connector.lbr             ← и т.д. — имена берутся из lib_id символов
├── my_project_footprints.lbr ← ВСЕ футпринты проекта для работы в glue
├── my_project.sch
└── my_project.brd
```

Библиотеки именуются по KiCad-библиотекам из которых пришли символы (`lib_id = "Device:R"` → `Device.lbr`).

---

## Ключевые решения

### Символы в схеме
KiCad хранит в `.kicad_sch` только **ссылки** на символы (`lib_id`), не геометрию.
Геометрия живёт в `.kicad_sym` библиотеках.

**Решение:** при открытии проекта проверяем каждый символ — встроена ли геометрия.
Если нет — показываем ошибку:
> "Схема содержит символы без встроенных данных. Откройте проект в KiCad, выполните embed символов, и возвращайтесь."
Со списком проблемных компонентов. Не пытаемся сами искать библиотеки.

### Футпринты в плате
`.kicad_pcb` хранит футпринты **целиком** — вся геометрия встроена. Внешние библиотеки не нужны.

### Библиотеки Eagle
Не пытаемся автоматически сопоставлять с существующими Eagle библиотеками — слишком высок риск тихой ошибки (одинаковый компонент, другие имена пинов). Создаём новые библиотеки, пользователь сам решает что с ними делать.

### 3D модели
Автоматически не переносятся — у пользователя свой GLB пайплайн, центр и угол модели относительно футпринта нигде не стандартизированы.

**Решение:** `_footprints.lbr` — отдельная библиотека со всеми футпринтами проекта. Пользователь открывает её в glue, централизованно присваивает GLB модели, делает downstream changes → 3D восстановлено во всех библиотеках проекта.

### Система координат
KiCad: origin левый верхний, Y вниз.
Eagle: origin левый нижний, Y вверх.
Конвертация: `eagle_y = board_height - kicad_y`

### DRC правила
Не конвертируются — всё равно диктуются производителем платы. Выставляем консервативные дефолты (0.2mm clearance, 0.25mm track), пишем пользователю что надо настроить под своего производителя.

### Иерархия схем
Различаем два случая:
- **Фиктивная иерархия (многостраничность)** — каждый `.kicad_sch` файл встречается в дереве ровно один раз. Это просто страницы. Конвертируется без потерь в Eagle `<sheet>` элементы внутри одного `.sch`.
- **Настоящая иерархия** — один `.kicad_sch` файл используется как лист более одного раза (повторно используемый блок). Пока не поддерживается — выдаём сообщение об ограничении. **Запланировано на следующую итерацию.**

### Multi-unit компоненты
Поддерживаются — Eagle тоже их умеет. Требует аккуратного маппинга через общий идентификатор компонента. Встречается редко (операционники, 74xx логика).

---

## Формат файлов

### KiCad `.kicad_pcb` / `.kicad_sch`
Текстовый S-expression формат. Читается парсером S-expr.

### Eagle `.lbr` / `.sch` / `.brd`
XML. Полностью документирован. Генерируется напрямую — никаких промежуточных Eagle скриптов.

---

## Что НЕ делаем
- Не ищем глобальные KiCad библиотеки на машине пользователя
- Не сопоставляем автоматически с существующими Eagle библиотеками
- Не конвертируем DRC правила
- Не переносим 3D модели автоматически
- Не пытаемся "починить" глубокую иерархию — отказываем с объяснением
